# Routing, 404 status and the sitemap

## Why the catch-all rewrite was removed

`vercel.json` used to contain:

```json
"rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
```

Vercel's request order is **redirects → headers → filesystem → rewrites**, so
that rule never affected a real page: `/pricing` matched `dist/pricing/index.html`
in the filesystem step and the rewrite was never reached.

It only ever applied to paths that matched *nothing* — and there it did real
damage. Every unknown URL returned **HTTP 200 with the homepage**:

- Google indexed unlimited duplicate URLs and wasted crawl budget on them.
- A mistyped or stale link showed the homepage instead of saying "this page
  doesn't exist", to both the visitor and the crawler.
- A missing image or asset came back as **HTML with status 200** rather than an
  error, so a broken media path could not fail loudly in monitoring.

The site is fully prerendered — every route in `src/AppRoutes.tsx` has its own
`dist/<route>/index.html` — so nothing needs the rewrite to survive a refresh or
a direct hit.

## How 404 works now

Two halves, and both are required:

1. **Server status.** `prerender.mjs` writes `dist/404.html`. Vercel serves that
   file, with a genuine `404` status, for any path matching no static file.
2. **Client-side UX.** `src/AppRoutes.tsx` has `<Route path="*" element={<NotFoundPage />} />`
   so an in-app navigation to a bad link renders the same branded page instead
   of a blank screen.

A client-side catch-all *alone* would have left the status at 200, which is the
bug this replaces. The React route is the polish; `404.html` is the fix.

`NotFoundPage` is `noindex, follow`, carries the VVE wordmark and design system,
and links to Home, Services, Pricing, Contact and Get a quote.

### Expected responses

| Path | Status |
|---|---|
| `/`, `/pricing`, `/gallery`, all 17 prerendered routes | 200 |
| `/leaflet` | 200 (but `noindex, follow`) |
| `/some-page-that-does-not-exist` | **404** + branded page |
| `/images/missing-file.webp` | **404** (was: 200 with HTML) |

## Sitemap

`public/sitemap.xml` was deleted. It is now generated by `prerender.mjs` from
the same `routes` array that drives prerendering, so:

- a new route cannot be added without appearing in the sitemap;
- only indexable routes are listed — `/leaflet` is `noindex` and is excluded,
  and the 404 page is neither a real URL nor indexable;
- `lastmod` comes from `git log -1 --format=%cs` for the files backing each
  route, so it reports when the page genuinely last changed.

On a shallow CI clone git can only see one commit, so every route falls back to
that commit's date. That is still true — the deployed content *is* that commit —
just less granular. No date is ever invented.

## Canonical host

Everything uses `https://www.vveclean.co.uk`. The apex redirects `308 → www`, so
pointing canonicals, `og:url`, sitemap `<loc>` and structured-data URLs at the
apex cost a redirect hop on every one and split signals across two hostnames.
